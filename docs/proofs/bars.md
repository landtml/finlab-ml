# finlab.bars: derivations and status of each claim

Component under test: [`src/finlab/bars.py`](../../src/finlab/bars.py) (AFML ch. 2).
Tests: [`tests/test_bars.py`](../../tests/test_bars.py). Benchmark: [`benchmarks/bench_bars.py`](../../benchmarks/bench_bars.py).

Every claim below carries one tag:

- **[proved here]**: a derivation is given in this document.
- **[checked by test]**: the implementation agrees with an independent naive reference on seeded inputs, or satisfies a stated invariant. This is evidence on fixed data, not a proof.
- **[claimed from the book only]**: taken from AFML and not proved or tested here. Some are empirical statements about markets.

## 1. Tick rule (AFML 2.3.2.1)

**Equation 2.1.** For prices `p_t`, `dp_t = p_t - p_{t-1}`, the tick rule is

    b_t = b_{t-1}          if dp_t = 0
    b_t = sign(dp_t)       if dp_t != 0,

with seed `b_0 in {-1, +1}`.

**Proposition 1.1 [proved here].** For every `t >= 1`, `b_t in {-1, +1}`, and `b_t` depends only on `(p_0, ..., p_t)` and the seed.

*Proof.* Induction on `t`. The base case holds because `b_0 in {-1,+1}` by assumption. For the step, either `dp_t != 0`, so `b_t = sign(dp_t) in {-1,+1}`, or `dp_t = 0`, so `b_t = b_{t-1} in {-1,+1}`. Both cases use only prices up to `t`. ∎

**[checked by test]** `_tick_rule` matches a Python transcription on seeded data, and it carries sign through zero-change runs (`test_tick_rule_*`). The book's boundary condition (`b_0` equals the terminal value of the previous bar) is realised because `b` is one global sequence across bars. The code does not reset it per bar.

## 2. Standard bars (AFML 2.3.1)

**Proposition 2.1 [proved here].** Let `x_t >= 0` be the per-tick increment (`x_t = 1` for tick bars, `x_t = v_t` for volume bars, `x_t = p_t v_t` for dollar bars), and let `h > 0` be the threshold. The kernel closes a bar at the smallest `T` with `sum_{t=s+1}^{T} x_t >= h`, where `s` is the previous closing index. Then:

1. Tick bars contain exactly `h` ticks (for integer `h`), and there are `floor(N / h)` closed bars for `N` ticks.
2. Each closed volume or dollar bar has total `x` at least `h`, and at most `h + max_t x_t` (overshoot is less than one tick's increment).

*Proof.* Let `S_T` be the running sum since the last close. Each tick adds `x_t >= 0`, so `S_T` is nondecreasing, and the first `T` with `S_T >= h` is well-defined. At the close, the sum resets to `0`. For tick bars `x_t = 1`, so the bar closes exactly when its count reaches `h`. Hence each bar has `h` ticks, and `N` ticks yield `floor(N/h)` complete bars. For (2), before the last tick the sum is `< h`, and the last tick adds at most `max_t x_t`. ∎

**[checked by test]** Tick, volume and dollar bars match a naive threshold loop with OHLCV aggregation to `1e-12` (`test_tick_bars_match_naive`, `test_volume_and_dollar_bars_match_naive`). Tick bar counts are asserted, and each volume bar would fall below its threshold without its last tick (minimal close), in `test_standard_bars_hit_threshold_exactly`. The overshoot bound `h + max_t x_t` of Proposition 2.1(2) is not asserted by any test. High/low/volume invariants hold (`test_bar_invariants`).

**[claimed from the book only]** Tick and volume bars give returns closer to IID normal (Mandelbrot and Taylor 1967; Ane and Geman 2000), and dollar bars are more stable under share-count changes (2.3.1.4). These are empirical claims, not tested here.

## 3. Imbalance bars (AFML 2.3.2.1-2.3.2.2)

**Definitions (book).** Let `s_t = b_t v_t` (with `v_t = 1` for tick imbalance, `v_t` the volume, or `p_t v_t` the dollar value). Within a bar starting after `s`, the imbalance is `theta_T = sum_{t=s+1}^{T} s_t`. The book's bar rule is

    T* = argmin_T { |theta_T| >= E0[T] * |E0[s_t]| }.         (Eq. 3.1)

The book writes the expectation as `E0[theta_T] = E0[T] * (2 P[b=1] - 1)` for tick imbalance and `E0[theta_T] = E0[T] (v+ - v-)` for volume and dollar imbalance (Eqs. in 2.3.2.1-2.3.2.2). Here `v+ = P[b=1] E0[v|b=1]`, `v- = P[b=-1] E0[v|b=-1]`.

**Proposition 3.1 [proved here] (expected imbalance).** Assume the pairs `(b_t, v_t)` are i.i.d., `T` is a stopping time for the filtration generated by them, and `E0[T] < infinity`. Then `E0[theta_T] = E0[T] E[s_t]`, and `E[s_t] = P[b=1] E[v|b=1] - P[b=-1] E[v|b=-1] = v+ - v-`. For tick imbalance this gives `E[b_t] = 2P[b=1] - 1`.

*Proof.* Wald's identity: if `(s_t)` is i.i.d. with finite mean and `T` is a stopping time with `E[T] < infinity`, then `E[sum_{t<=T} s_t] = E[s_1] E[T]`. For the decomposition, `E[s_t] = E[b_t v_t] = P[b=1] E[v|b=1] + P[b=-1] E[-v|b=-1]`, by the law of total expectation over `b_t in {-1,+1}`. Writing `v+ - v- = 2 v+ - E[v]` with `E[v] = v+ + v-` gives the form the book uses. ∎

*Remark.* The stopping-time and i.i.d. hypotheses are not stated in the book. Without them the book's formula is a heuristic approximation.

**Estimator (book, 2.3.2.1-2.3.2.2).** The book says to estimate `E0[T]` by an EWMA over prior bars and `E0[s_t]` by an EWMA over prior ticks. Our implementation uses the EWMA in closed form. For a sequence `x_1..x_H`, starting value `E_0`, and `alpha = 2/(span+1)`, the recursion `E <- alpha x + (1-alpha) E` gives

    E_H = (1-alpha)^H E_0 + sum_{j=1}^{H} alpha (1-alpha)^{H-j} x_j.       (Eq. 3.2)

*Proof of Eq. 3.2.* Induction on `H`. For `H = 0` both sides equal `E_0`. Substituting `E_{H-1}` into the recursion gives `E_H = alpha x_H + (1-alpha) E_{H-1}`, and the closed form for `H` follows. ∎ **[proved here]**

**Implementation choices (not in the book).**

- `E0[T]` starts at `init_T`. The per-tick expectation `E0[s_t]` starts as the mean of the first `min(init_T, N)` values. This bootstrap is the only look-ahead in the estimator. It affects only early bars.
- Expectations are frozen while a bar is open. At close, `E[T]` is updated with the bar length, and `E[s]` with each tick of the closed bar in order.
- Threshold `E[T] * |E[s]|` is recomputed at each bar start.

**[checked by test]** Each kernel agrees with a naive reference that evaluates Eq. 3.2 in closed form over the full history, for all three kinds and several seeds (`test_imbalance_bars_match_naive`). The reference uses independent code. The monotone-tape test (`test_imbalance_threshold_is_exact_on_a_monotone_tape`) checks the threshold rule exactly: with `b_t = 1`, `E[s] = 1`, `E[T]` stays `init_T`, and every bar has `init_T` ticks.

**Degenerate case [proved here].** If `E[s] = 0`, the threshold `E[T] |E[s]|` is `0`, so every tick closes a bar. The rule does not define a sensible bar in that case. The code does not guard against it. This is a documented limitation.

## 4. Runs bars (AFML 2.3.2.3-2.3.2.4)

**Definitions (book).** Tick runs: `theta_T = max{B_T, S_T}` with `B_T = #{t <= T: b_t = 1}` and `S_T = #{t <= T: b_t = -1}`. Volume and dollar runs replace the counts with `sum v_t` over the buy and sell sides. The bar rule is `theta_T >= E0[T] * max{E0[buy], E0[sell]}`, with `E0[buy] = P[b=1] E0[v|b=1]` and `E0[sell] = (1-P[b=1]) E0[v|b=-1]` (with `v = 1` for tick runs).

**Proposition 4.1 [proved here] (expected value of a run count under Wald).** Under the hypotheses of Proposition 3.1, `E0[B_T] = E0[T] P[b=1]` and `E0[S_T] = E0[T] P[b=-1]`.

*Proof.* Apply Wald's identity to the i.i.d. indicators `1{b_t = 1}` and `1{b_t = -1}`. ∎

**Remark on the book's threshold [proved here].** The book writes `E0[theta_T] = E0[T] max{P[b=1], 1-P[b=1]}`. Under the same hypotheses, the expected run count `E0[max{B_T, S_T}]` satisfies `E0[max{B_T, S_T}] >= max{E0[B_T], E0[S_T]}` by Jensen's inequality, for the convex function `max`. The inequality is strict unless one side is almost surely zero. The book's threshold is therefore the max of two expectations, not the expectation of the max. This is a choice, and the code implements the book's threshold as written, with `max{E[buy], E[sell]}` from the EWMA estimates.

**[checked by test]** The kernel matches a naive reference with closed-form EWMA estimates, for all three kinds (`test_run_bars_match_naive`).

## 5. CUSUM filter (AFML 2.5.2.1, Snippet 2.4)

**Recursion (Snippet 2.4).** With `y_t = x_t - x_{t-1}`,

    S+_t = max(0, S+_{t-1} + y_t),   S-_t = min(0, S-_{t-1} + y_t),

and an event is emitted at the first `t` with `S-_t < -h` or `S+_t > h`. The emitting side resets to `0`.

**Lemma 5.1 (Lindley identity) [proved here].** For `t >= 0`, with `S_0 = 0`,

    S+_t = max_{0 <= tau <= t} sum_{i=tau+1}^{t} y_i,   S-_t = min_{0 <= tau <= t} sum_{i=tau+1}^{t} y_i,

with the empty sum (`tau = t`) equal to `0`.

*Proof.* Induction on `t`. For `t = 0`, both sides are `0`. For the step, `max(0, S+_{t-1} + y_t)`: by hypothesis `S+_{t-1} = max_{tau <= t-1} sum_{i=tau+1}^{t-1} y_i`, so `S+_{t-1} + y_t = max_{tau <= t-1} sum_{i=tau+1}^{t} y_i`. Taking the max with `0`, which is the empty sum for `tau = t`, gives the claim. The argument for `S-` is symmetric. ∎

**Consequence [proved here].** Between resets, `S+_t > h` iff some partial sum since the last reset exceeds `h`. This is the book's "exists tau with |sum y_i| >= h" event (2.5.2.1), up to the strictness below.

**Strictness.** The text writes `S_t >= h`, but Snippet 2.4 uses `> h` and `< -h`. This module follows the snippet. The two differ only when a partial sum equals `h` exactly, a measure-zero event for continuous data.

**[checked by test]** `cusum_filter` matches a loop transcription of Snippet 2.4 on levels and on returns, with a seeded input (`test_cusum_*`).

**[claimed from the book only]** The CUSUM filter avoids the repeated triggering that Bollinger bands suffer near a threshold (the text after Snippet 2.4). That qualitative claim is not tested.
